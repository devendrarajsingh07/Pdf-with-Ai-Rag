# API / Gemini security and readiness — 2026-10-08

## Verdict

The local Redis/key and known dependency-advisory blockers are resolved. Real Redis 7.4.11 runs in WSL Ubuntu-24.04 on loopback port 6380 with password authentication and AOF persistence. Backend and ML run in queue mode with a retained AES-256-GCM key protected by Windows CurrentUser DPAPI and owner/SYSTEM-only permissions. Actual `.env` files were not changed. Full npm audits and the installed Python environment audit report zero known vulnerabilities. Docker remains absent; Docker deployment was not verified. This is not public-production security certification: deployment controls and operational gaps below still need review. `/api/v1/health` is liveness only; coordinated readiness returned HTTP 200 with database, ML, Redis and queue checks true.

## Implemented request flow

1. Express verifies the cookie/JWT (HS256 only), user existence and Origin for mutations. Chat/document service methods check resource ownership. Upload size/signature and pre-upload per-user limits apply.
2. In queue mode, a 16–128 character `Idempotency-Key` is required. PostgreSQL serializes each owner/key using an advisory transaction lock. A keyed SHA-256 digest identifies the key; a request fingerprint rejects same-key/different-body reuse with 409. Exact replays return the existing job before consuming Redis admission again.
3. Redis atomically admits up to `USER_API_REQUESTS_PER_MINUTE` accepted new jobs (default 20/min per owner). Redis errors fail admission closed with 503. This does not replace stricter route/IP limits.
4. PostgreSQL commits the job and, for uploads/reindexing, document metadata/status in the same transaction. The sensitive job payload, including its owner ID and raw idempotency key, is AES-256-GCM encrypted with a fresh 96-bit nonce, a 128-bit authentication tag, and job/owner/type associated data. Raw keys are never returned in status/audit JSON. Bcrypt remains password-only; it is not encryption. Lookup digests are intentionally not decryptable; the encrypted payload is reversible only with the separate data key.
5. Workers claim PostgreSQL rows using `FOR UPDATE SKIP LOCKED`. Chat has priority 0, document processing priority 1. Within tiers, smaller estimated durations run first. Jobs waiting over five minutes move ahead of new jobs in FIFO order. This is non-preemptive estimated SJF, not true preemptive SRTF/SJTF: running external requests cannot be interrupted safely. Estimates use question length/file size, not measured CPU time.
6. Two-minute leases renew every 30 seconds. A unique partial index permits only one processing job per resource. Fencing prevents a stale worker from committing. Expired leases can be reclaimed up to three attempts; explicit processing failures are terminal and require a new request/reindex, rather than endless automatic retries.
7. OCR retains source PDFs and native text, scans significant image regions, reports confidence/word counts/warnings, and creates extractive summaries from every page. Queued document processing verifies the source SHA-256 before and after ML execution. Optional encrypted Redis extraction/index checkpoints assist diagnosis; they are not the authoritative job store and are not automatically replayed. Source PDFs remain available for re-extraction.
8. ML reserves Redis per-model request/token budgets and a shared project request budget before every upstream attempt. Defaults are application budgets, not discovered Google account quotas; input token counts are approximate character-based estimates and cannot guarantee Google TPM accounting, especially for non-Latin text or reasoning tokens. Cache hits avoid upstream calls. Generation/text/vector caches are user-scoped, encrypted, model/config/content keyed, and expire (generation 300 seconds, embeddings 3600 seconds). Extraction/index checkpoints expire after 24 hours. Cache-write failure does not discard successful results.
9. Generation can fall back to `gemini-3.7-flash`, then `gemini-3.5-flash` after primary `gemini-3.8-flash` encounters 429 or transient 5xx/budget exhaustion. All three appeared in the configured account's model list. No fallback for 401/403, malformed requests or safety refusals. Shared project caps remain in force. The user must already have passed admission. Embedding models are not silently swapped: different embedding spaces require a separate collection and reindex.
10. Chat messages and the completed encrypted job result commit in one PostgreSQL transaction. PDF readiness/analysis and completed job result likewise commit together. The owner polls `GET /api/v1/jobs/:id`; another owner gets 404. See `REQUEST_TRANSACTION.schema.json` for the complete status/audit envelope. Logs use request IDs, user-ID digests, stages and generic codes, not document text or raw keys.

## ACID / data-loss boundaries

PostgreSQL transactions provide atomic local row changes. Gemini, files, Redis and Qdrant cannot participate in that transaction. This is an at-least-once, checkpointed workflow, not distributed ACID or exactly-once billing. A crash after a Gemini response but before cache/database persistence may repeat a billable call. Qdrant upserts and stale-point deletion are separate remote operations; crashes can leave temporary stale vectors. Redis AOF `everysec` can lose approximately a second of recent coordination/cache writes, but job admission/payloads remain in PostgreSQL. Disk/database backups and key backups are essential.

Encryption covers job request/results and Redis caches/checkpoints. It does **not** encrypt all existing user data: names/emails, normal chat rows, document analysis, source PDF files and Qdrant payload text retain their current representations. Full at-rest protection needs encrypted volumes/database deployment, backup encryption, or a separately designed column/file/vector encryption migration. TLS is required in deployment; AES does not replace transport security. The encryption key must be separate from JWT, ML-service and Gemini credentials; losing it makes retained job/cache ciphertext unrecoverable. Automatic key rotation/multi-key decryption is not implemented.

## Fixed / reduced attack surfaces

- `.dockerignore` files prevent actual `.env` files, local dependency trees and runtime uploads from entering Docker build contexts. Existing `.env` files were not edited.
- Docker Node images now use Node 22 rather than Node 18; ML and Qdrant Compose ports bind to loopback. Redis has no published host port, requires a password, persists AOF, has a 256 MiB cap and `noeviction` (coordination keys must not silently vanish).
- PDF.js dynamic evaluation is disabled (`isEvalSupported: false`) as a mitigation for malicious PDF font evaluation in the existing viewer. This is not a claim that every PDF.js advisory is fixed.
- Next.js was upgraded to 15.5.27, React-PDF to 10.5.0 and its matching PDF.js to 5.4.296. The matching local worker is copied at build time to `public/pdf.worker.min.mjs`, replacing the obsolete generated `.js` worker. Tailwind 4 and patched backend/ML dependencies were verified; native frontend startup defaults to loopback.
- JWT verification explicitly permits HS256 only. Question/title/document-list sizes, Express JSON size and multipart counts are bounded. Uploaded-file type is checked by magic bytes, not MIME alone.
- Pre-upload limit is 3/min per user; chat sends remain 20/min per user. General/auth limiters remain process-local. Queue-mode Redis admission is shared across replicas.
- Document text remains data, not instructions. Short PNR lookups use extracted identifiers and explicitly disclaim live railway status; arbitrary live PNR lookup was not added.

## Remaining vulnerabilities / operational gaps

1. **Dependency maintenance:** full and production-only npm audits report zero advisories for both applications. `pip-audit` reports no known vulnerabilities in the installed Python environment; `pip check` passes. These are point-in-time scans, not proof of absence of vulnerabilities. Drizzle, Multer, Jest, FastAPI/Starlette, PDF parsers, Transformers, Sentence Transformers and docTR were upgraded. eslint-config-next 14.2.35 deliberately retains established lint rules with the Next 15 runtime: newer lint plugins introduce an unpatched braces dependency. Scoped glob/esbuild overrides and a js-yaml 4 override remove tooling advisories; YAML compatibility and unsafe-tag rejection have regression tests. Python requirements pin direct packages but do not lock every transitive dependency.
2. **Secrets / key readiness:** actual Gemini key material was never printed or included in these files. Its account model-list access works; Google Cloud project restrictions, billing caps, key rotation history and deployed secret access controls cannot be determined from source. Restrict the key to the required API, keep it server-side in a secret manager, monitor spend/quotas, and rotate if previously exposed. Browser bundles must never receive `GEMINI_API_KEY` or `ML_SERVICE_TOKEN`.
3. **Local infrastructure exposure:** the existing native Qdrant installation is preserved; its bind address/authentication are not hardened by Compose edits. Do not expose it publicly. PostgreSQL port publishing, ingress TLS, network policies, Redis TLS/ACLs and firewall settings need deployment review. Compose's basic password authentication is not tenant isolation.
4. **Storage / upload abuse:** no per-user disk quota, antivirus, PDF decompression sandbox or bounded PDF-page count exists. Replayed uploads can leave additional disk files because upload bytes are saved before the database recognizes the duplicate; pre-upload throttling reduces but does not eliminate this. No existing uploads were deleted in this work.
5. **Token / auth lifecycle:** no JWT revocation list, MFA or account deletion. Logout clears the browser cookie but does not revoke copied tokens. Register responses disclose duplicate emails. All rate limits must be configured to actual account/deployment needs; auth/IP limiters are not distributed.
6. **Queue lifecycle:** PostgreSQL polling every 500 ms and the soft 1000-job backlog cap are suitable for a small deployment, not unlimited throughput. Worker counts should stay within DB/ML limits. Graceful worker shutdown, durable retry backoff for failed jobs, dead-letter administration and automatic job/audit retention are not implemented. Pending jobs block user deletion through a foreign key until an explicit retention policy exists.
7. **Idempotency lifecycle:** keys are retained indefinitely with jobs; digesting currently depends on JWT_SECRET, so JWT secret rotation requires an idempotency-hash migration/retention decision. Frontend generates a key per submission, not a durable browser intent store for offline/reload retry. Clients needing replay must retain and reuse their original header value. Not every CRUD route is idempotent—queue protection covers chat sends, upload and reindex.
8. **Redis/key reliability:** real Redis authentication, atomic admission, encryption/AAD rejection, persistence settings and the AOF manifest were verified. Crash recovery and backup restoration were not exercised. Monitor the 256 MiB `noeviction` instance and disk capacity. The ignored secret file `.tools/secrets/runtime-secrets.clixml` is DPAPI-bound to the Windows user/profile: copying this file alone is not portable disaster recovery. Production needs managed secrets, tested key/data recovery and rotation. Redis uses loopback/password authentication, not configured TLS or fine-grained command ACLs. Configured Redis outages fail provider reads/limits closed.
9. **Migration caveat:** the installed Drizzle Kit omitted the partial-index predicate when generating `0003_watery_arclight.sql`. It was corrected manually to `WHERE status = 'processing'` and exercised against the isolated test DB. Review future generated index migrations for this predicate.
10. **OCR limits:** confidence is not ground-truth accuracy. English Tesseract is used; scan rotation, handwriting, very small image regions and multilingual documents are not comprehensively handled. Native PNR layout association uses conservative spatial heuristics; verify numbers against the source. Date tokens are recognized text, not calendar validation. Airline alphanumeric booking locators are not the same as the ten-digit railway PNR matcher.

SDK-internal HTTP retries are disabled so each outer generation/embedding attempt is budgeted explicitly; individual HTTP calls have a 90-second timeout. Processing timeout reconciliation requires an encrypted completion checkpoint for the exact owner/request/document, written after indexing and stale-point cleanup. Old or partial chunks are not proof of a successful reprocess. Without configured Redis, a timed-out result cannot be confirmed and is marked failed rather than falsely ready; the source file is retained for retry.

## Enabling the Compose path

Install/start a Docker engine first. Supply root `REDIS_PASSWORD` and `DATA_ENCRYPTION_KEY` through a secret manager or process environment; no existing `.env` was modified. Generate a random 32-byte key encoded as base64, retain it securely, and use the same key in backend and ML. Redis passwords in URLs must be URL-safe/encoded. Set real provider budgets in ML configuration to match AI Studio quotas. Then run:

```text
docker compose up -d --build
docker compose exec backend npm run db:migrate
docker compose restart backend
```

For a fresh database, backend startup may fail until migrations are applied; restarting after migration is required. Set `QUEUE_ENABLED=true`, `REDIS_URL`, and `DATA_ENCRYPTION_KEY` on both coordinated services for native deployment. Queue mode refuses to start without Redis/key configuration. Do not expose the current app publicly while blockers above remain.

# Neural OCR security addendum (2026-10-08)

The cGAN/docTR integration preserves source PDFs and never accepts checkpoint/source-code paths from public API bodies. Upstream GAN code is executable, pinned trusted deployment code. Checkpoints must be trusted document-trained state_dicts: `weights_only=True`, strict architecture matching, 1 GB cap and optional SHA-256 digest. A digest is not a model-quality or universal pickle-safety guarantee. No arbitrary checkpoint URL fetching is supported. Native mode uses a trusted ignored upstream checkout; deploy model files read-only. Official docTR weights are cached on first use and require outbound access unless prewarmed.

Serialized per-process OCR, a 16 million pixel raster cap, bounded GAN tiles and finite-output checks reduce resource risks but are not hard CPU-time/RAM isolation. Full PDF page count remains an independent workload-size risk. Structural OCR JSON includes private words/coordinates and is owner-protected like existing analysis; JSONB is not globally encrypted at rest by this feature. Optional Redis checkpoints remain encrypted. Log files may include internal exception paths, not source OCR text. Enhancement can hallucinate/change digits; integrity checks are heuristics, not an accuracy or no-data-loss guarantee. No training checkpoint was supplied and GAN enhancement is inactive by default. This addition does not resolve previously documented API/dependency vulnerabilities.
